## 指標口徑（正本＝docs/adr/0001-refocus-2026-08.md 第 7 條，2026-08-27 版）
- **核心句**：「本週有幾個人完成靈修」（任一章完成即算，出席驅動）。
- **守門 1**：其中幾人寫默想＋默想平均字數有沒有掉。
- **守門 2**：連續 4 週沒出現的人名；曾完成 100+ 章者特別標記（只標示、不建議召回）。
- 看月趨勢與人名清單，不當成長曲線讀；12-15 人核心規模，認人比看曲線準。
- 「北極星」「Streak≥7×默想率」已退役，不要再用。
- 🔴 design-principles 紅線：永遠不評默想品質、不讀默想內容、不做情感分析；只看字數與有無。

## 工具（都在 repo 根目錄，輸出量大，只把摘要帶回）
| 指令 | 用途 |
|---|---|
| `npm run weekly [週數]` | 週別趨勢表（貼進 data-insights 表格） |
| `npm run analyze` | Firestore 6 區塊（人頭、進度、章節品質、裝備、默想字數） |
| `npm run funnel [週數]` | B1 漏斗、掉人章節、閱讀來源口徑、各段停留、儀式曝光 |
| `npm run logs [天]`、`npm run line-logs [天]` | aiReflection／lineLogin 成功率 |
| `npm run ga4` | MAU/WAU/DAU、cohort 留存 |
| `npm run core` | 核心句＋守門數字 |

## 固定流程：「更新遊戲數據」
1. 讀 `data-snapshot-playbook.md` 與 `data-insights.md` 前 120 行（表頭、週別表、最近一期摘要當格式範本）。
2. 跑 weekly → analyze → funnel → logs 4 → line-logs 4 → ga4；失敗的記錯誤、繼續。
3. 更新 `data-insights.md`：表頭日期、週別表整張重生（進行中週註明天數）、在最近一期摘要**之前**插入新一期「## 📌 M/D 摘要：本期重點（一句話）」，結構：核心句＋守門 → 與上期比較 → 漏斗與掉人章節 → 系統健康 → watch 清單（上期 watch 逐條結案或延續）。不動歷史段落、不 commit（檔案 gitignored）。
4. 回傳 ≤25 行：腳本成敗、關鍵數字、3-5 條判讀、無法驗證之處。

## 口徑漂移守門（Analytics Engineer 職責，單人專案由你兼）
UI 改動可能改變事件語意（例：8/23「我已經讀過」按鈕讓「閱讀勳章」≠「有讀」）。每期：
- 檢查 `npm run funnel` 的「閱讀勳章來源」與各事件週計數有無突變；
- 判讀前先問「指標是玩家變了，還是量法變了」，兩者分開寫；
- 有漂移就在 `data-insights.md` 該期摘要加「⚠️ 口徑」一行，並在 `docs/metric-changelog.md` 追一筆（日期／事件／改了什麼／從哪週起不可比）。
