## 三、未爆彈與陷阱

**① cherry-pick 看不出「上了沒」**
本專案發布走 cherry-pick，產生的是**同訊息、不同 SHA** 的副本。
看 dev 的 commit 訊息或分支領先關係，永遠判斷不出某批是否已在 main。
**一律用 grep 對帳 main 的實際內容。**
這輪至少三個人栽在這裡（PM、開發視窗、CC 交接文件）。

**② 未推的工單是雷**
工單結尾若寫「停在 push 前」，必須追到 push 完成才算結案。
本地 main/dev 領先遠端時，下一批發布的 Phase 0 會撞錨點偏差。
已發生兩次（9B 發布、GEN1-5 發布）。

**③ 共用工作樹**
內容視窗、開發視窗、PM 視窗共用同一工作樹。
**所有 commit 一律明列檔案，禁止 `git add -A`。**
唯讀工單也要禁止 `git status` / `git fetch`（會留 `index.lock` 擋住其他 session）。

**④ `pm-ga4-card` worktree 不可砍**
它是數據視窗的活 worktree（`62a2eb6`）。
git 清潔只能砍 `ga4-bugfix` 與 `phase-3c-admin` 兩個。

**⑤ 提前靈修路徑：沒有修正窗口**
日曆有 `isFuture` 分支，內容一上 main 玩家當天就能全部讀完，
不必等排程日。**發布後沒有「還來得及改」這件事。**

**⑥ hkbs 來源的靜默失敗**
`/CUNP/` 與 `/CUNPSS/` 皆回 HTTP 200，但內容是**和修版**。
唯一正確來源是 `https://rcuv.hkbs.org.hk/CUNP1/{書卷}/{章}/`，
抓取後須查驗 title 為「新標點和合本(神)」。

**⑦ 敏感文件在 public repo**
repo 是 public，被追蹤的檔案任何人都看得到。
`data-insights.md` 內有玩家代稱與行為描述——在 50 人的教會小圈子裡，
「連續破百天的那位」幾乎等於指名道姓。**匿名化在小社群無效。**
repo 不能轉 private（Pages 會失效），路徑是「敏感文件不進 repo」。
